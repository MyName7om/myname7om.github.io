Creating a Home Server Using a RaspberryPi and Docker

May 20, 2025 2-minute read

The use of my RaspberryPi was discussed in the previous post, however I changed how I am using it. After countless YouTube videos, I decided to use Docker instead of ProxMox, there are reasons for this change, however the main reason was I have never used Docker but I have had some experience with a level 1 hypervisor.

Overview Link to heading

  • RaspberryPi 4 8GB memory
  • For the Docker containers I have implemented at this moment:
    • PiHole: DNS blocker, used for an add blocker.
    • Portainer: Used for the web GUI for managing Docker.
    • Plex: Locally hosted version of Netflix.
    • Ubuntu: Virtual Ubuntu Linux machine, this is similar to just SSHing into my Pi but it is easier to delete the container and start again if I mess up.
  • The Docker containers I would like to implement next:
    • Gitlab
    • Blog, slef-hosted
    • Hashicorp
    • Tor IRC, through either a designated IRC container or through an Ubuntu container
    • Some sort of NAS type system

Note This is just the start, I plan on continuously growing the server and adding more and more containers to make it more interesting and potentionally more usefull!

What I found Link to heading

Docker has been really fun to play with so far, I was surprised how easy it was to use. I installed containers in multiple ways, through creating .sh files, creating yaml compose files and through Portainer (all GUI). However, I have ran into a problem, recently I have been looking into using Kubenetes and I might need to restart this project using Kubetes alongside Docker. This is the only issue I have come across, as for every other thing I am wanting to try I can create a container in Docker to do it. Installing and using Kubenetes would mean starting this project all over again!
